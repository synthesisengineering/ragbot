# Third-party modules required for Ragbot.AI
#
# Floors track the latest stable release of every direct dependency (raised
# 2026-11-06, on Python 3.14). Upper caps exist only where a new major broke
# Ragbot or an upstream pairing (mcp, openai); each cap says why. Packages
# still held below their latest release are held by caps in the newest
# release of the package that depends on them — see
# docs/security/dependabot-triage-2026-11.md, "Held back upstream".

# --- Provider SDKs --------------------------------------------------------
# Versions track the post-March-2026 LiteLLM supply-chain incident: the
# compromised range was 1.82.7-1.82.8. See
# https://docs.litellm.ai/blog/security-update-march-2026.
#
# The floor was 1.83.0 — the first release after that range — and stayed there
# because it was the minimum, not because it was the intent. On 2026-09-03 the
# resolver was found pinning litellm to exactly 1.83.0, so the default gateway
# was running the oldest version the incident permits and had been for months.
# The floor is now the current release: being just past a known-compromised
# range is not the same as being current, and a security floor that never
# moves is a ceiling.
anthropic>=2.6.0
# openai 3.x is allowed because LiteLLM now accepts it. LiteLLM 1.108.0 is the
# first release to declare `openai<4.0.0`; every release from 1.90.0 through
# 1.106.7 caps openai below 3. The LiteLLM floor below is 1.108.0 for that
# reason, so the two bounds state the pairing directly.
#
# Keep the history in mind. On 2026-09-03 a bare `openai>=3.6.0` resolved by
# reaching back to LiteLLM 1.83.0, the one release old enough not to forbid
# openai 3, and installed a pairing upstream forbade everywhere it knew to. It
# installed, `pip check` passed and the suite passed, because provider calls are
# mocked. A floor raised on one package can drag another backwards; the guard
# is a matching floor on the other side. See
# docs/security/dependabot-triage-2026-09.md and dependabot-triage-2026-11.md.
#
# Call sites verified against openai 3.46.0 on 2026-11-06: `openai.OpenAI()`
# with `organization`, `chat.completions.create` including streaming, and the
# module-level `openai.api_key`.
openai>=3.46.0,<4
# google-genai is the current Google SDK. The end-of-life google-generativeai
# package was dropped on 2026-11-06: nothing in Ragbot imported it and no
# other dependency required it, but it pinned google-ai-generativelanguage
# 0.6.15, which held protobuf below 6 and google-api-core, proto-plus and
# grpcio-status at old releases.
google-genai>=3.0.0
# Capability-only registration must preserve missing prices and explicit effort.
# Verified offline transformation: docs/model-catalog-2026-11-06.yaml.
# 1.108.0 is the first release that accepts openai 3 (see above).
#
# The floor is the 1.109.0 release candidate because it is the first LiteLLM
# that accepts filelock 4: every release from 1.104.0 through 1.108.1 caps
# filelock below 4, and filelock 3.x carries 13 CVEs fixed only in 4.x. pip
# installs the candidate today and moves to 1.109.0 itself once it is released,
# since the final release satisfies this floor.
litellm>=1.109.0rc1
# Transitive (torch, huggingface_hub, litellm), declared so the patched major is
# the floor (4.2.1 fixed the CVEs that 3.32.7 carries; 4.2.9 is the latest).
filelock>=4.2.9

# --- Model Context Protocol ----------------------------------------------
# The official Python SDK powers synthesis_engine.mcp (client, primitives,
# OAuth, Tasks, the stdio-to-HTTP proxy) and synthesis_engine.mcp_server.
#
# Ragbot moved to mcp 2.x on 2026-11-06. 2.x is a redesign, not a rename: the
# low-level server takes handlers as constructor arguments and leaves tool-call
# semantics (schema validation, structured output, error results) to them;
# the client's experimental tasks namespace is gone, so synthesis_engine.mcp.tasks
# sends the 2025-11-25 task requests itself; types use snake_case attributes.
# See docs/security/dependabot-triage-2026-11.md.
#
# The `<3` ceiling stays for the reason it was added on 2026-09-03: with a
# floor alone, pip takes the newest major, and the 1.x-to-2.x jump showed a
# major can break every MCP module at import time.
mcp>=2.3.0,<3
# Imported directly: synthesis_engine.mcp.transport builds the httpx2 client
# that mcp 2.x's Streamable HTTP transport takes, and the MCP server validates
# tool arguments and results with jsonschema. Both also come in through mcp;
# declaring them keeps a direct import from depending on another package's
# dependency list.
httpx2>=2.16.0
jsonschema>=4.26.0
